# Devpost draft (truthful working copy)

Title: Reify — From thought to action

Problem: People plan in handwritten lists, diagrams and scattered notes. Moving that intent into software often loses conditions and uncertainty.

Solution: Reify offers three input formats, a server-side Gemma 4 interpretation path, editable dependency graphs, targeted clarification and exact-action approvals. A deterministic demo engine waits for verified fictional replies and availability before storing a fictional study-room reservation, then verifies its saved confirmation.

Built with: Next.js App Router, React, TypeScript, Tailwind, React Flow, Zod, Google GenAI SDK, Vitest and Playwright.

Actually demonstrated on Windows: labeled fixtures, clarification, graph editing, human approvals, persisted demo reservation and confirmation evidence. Live Gemma inference was not run because no key was supplied. Twinly official adapter exists and has mocked contract tests; live Mac integration is pending. No real messaging or university room reservation has been performed.

Challenges: untrusted model JSON, ambiguous dates, unknown replies, stale approvals, DAG validation, deduplication and honest provider status.

Frontier technology: intended central model is gemma-4-26b-a4b-it. Verify release date and run actual text/image calls before claiming the frontier category. Candidate categories: Gemma / Twinly / open-source AI, subject to organizers' actual eligibility rules. No prize claim is established.
